循環一說明

📚 知識庫編譯循環

• 重複執行：每匯入一篇新文獻（如水分、糖尿病、心臟病）即重複此循環一次。
• 檢查機制：在寫入前「先討論確認」，寫入後以 Lint 工具檢測斷鏈與孤立頁面。
• 設計理由：確保進入知識庫的事實 100% 正確，避免將錯誤資訊擴散至下游。

循環二說明

🎨 產品生成與檢驗循環

• 重複執行：根據受眾理解難度在大綱層級迭代調校。
• 檢查機制 (Shift-Left)：將檢查前移至「大綱與風格審查」，先核對通俗比喻與動漫風規範，確認才寫代碼。
• 設計理由：杜絕在幾百行 HTML 中重構知識的痛苦，確保一次生成即成功。
